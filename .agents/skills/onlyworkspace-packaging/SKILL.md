# Packaging workflow

- Read `docs/admin/installazione.md`, `scripts/build-installer.ps1` and `installer/OnlyWorkspaceSetup.nsi` before changing setup behavior. `pwsh -NoProfile -File scripts/build-installer.ps1 -Configuration Release` builds, tests, signs and creates a new package directory containing `publish/` and `dist/OnlyWorkspaceSetup.exe`; `-OutputDirectory` selects a new destination. Existing packages are retained. `-SkipTests` skips only the script's .NET test step; even the default invocation does not replace the complete gate in `docs/tecnico/verifica.md`.
- Compare the signer with `certs/OnlyApps.cer` when diagnosing trust errors; a timestamp or embedded signature does not establish trust. `Directory.Build.props` supplies the version to NSIS. The package ships net48; tray and add-in must match the pipe contract. Signing inputs and identity constraints remain in `docs/admin/installazione.md`.
- Read-only checks: `pwsh -NoProfile -File scripts/register-addin.ps1 -CheckOnly` and `pwsh -NoProfile -File scripts/block-new-outlook.ps1 -Action Check`. Registration exit 0 covers machine registration and an existing CodeBase in the applicable registry views; a per-user disabled add-in is only warned about. It neither matches CodeBase to the supplied AssemblyPath nor proves Outlook loaded the add-in. Policy Check returns 1 when any expected HKCU/HKLM value is absent/different.
- Registration/unregistration are development-machine mutations, with elevation and Outlook closed as preconditions; their scripts do not enforce those preconditions. `-AssemblyPath` defaults to Release output, not the installed DLL. Policy Apply/Revert affect HKCU and, when elevated, HKLM; diagnose with Check before deciding which environment to change.
- Office No-PIA metadata is applied to `ReferencePath` after `ResolveReferences`; metadata on `PackageReference` does not reach the compiler. Check actual assembly references and packaged files: the packaging gate reads every distributed managed assembly before removing stale PIAs. `InteropPackageTests` checks the compiled add-in and restored Microsoft signatures; signatures do not establish redistribution terms. Credits and notices are maintained in `src/OnlyWorkspace.Core/ThirdPartyComponents.cs` and `THIRD-PARTY-NOTICES.txt`.
- `pwsh -NoProfile -File tests/scripts/Packaging.Tests.ps1` uses command doubles, a temporary certificate and NSIS fixtures; it does not sign/install the real package. Setup checks that must stay testable (WebView2 `pv` validation, `CheckExecResult` after every critical `nsExec` command, bare `/PURGE` and the purge targets) live in `installer/SetupChecks.nsh`, run there in a user-level silent fixture on synthetic data; keep new critical commands followed by `CheckExecResult`. icacls `/C` exits 0 even when files fail. For runtime smoke, run `scripts/smoke-net48.ps1` under Windows PowerShell 5.1 x64 and x86: its default resolves the current Release output through MSBuild. See `docs/tecnico/output-locali.md` for central artifacts and retained fixtures. Shared gates and installed-build qualification remain in `docs/tecnico/verifica.md`.
