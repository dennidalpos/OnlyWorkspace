# OnlyWorkspace development

- Commands below use PowerShell at the repository root; shared gates and constraints are in `AGENTS.md`. Use the focused [archive](../onlyworkspace-archive/SKILL.md), [LLM](../onlyworkspace-llm/SKILL.md), [ConfigTool](../onlyworkspace-configtool/SKILL.md), [attachments](../onlyworkspace-attachments/SKILL.md), [packaging](../onlyworkspace-packaging/SKILL.md), or [assets](../onlyworkspace-assets/SKILL.md) skill for those workflows.
- Trace add-in lifecycle in `src/OnlyWorkspace.Outlook/OnlyWorkspaceAddin.cs`, Outlook access in `src/OnlyWorkspace.Outlook/Services/OutlookDataService*.cs`, and pane dispatch in `src/OnlyWorkspace.Outlook/UI/TaskPaneCoordinator*.cs`. The coordinator is split into partial files; check the affected action rather than only the main file.
- For asynchronous Outlook paths, inspect `src/OnlyWorkspace.Outlook/UI/UiSync.cs`: Office callbacks may lack a WinForms synchronization context. Preserve the UI context across awaits before further Object Model calls, pass plain data to background work, and release acquired COM objects deterministically.
- Use `Services/UiSlice.cs` to yield between long Outlook Object Model reads; repeated `Task.Yield()` posts continuations that can starve input and paint ([Microsoft](https://learn.microsoft.com/en-us/dotnet/api/system.threading.tasks.task.yield?view=netframework-4.8.1)). Keep watchdog activity scopes on synchronous work, not across awaits.
- Pane first-open timings name CreateCTP, control constructor, coordinator, show and WebView2 initialization separately. Ribbon logs also record the whole callback and heartbeat age on entry/exit; queued WebView time and the synchronous EnsureCoreWebView2Async call are separate from total asynchronous initialization. Do not attribute a heartbeat delay to the callback from phase sums alone. OnCreateControl posts WebView initialization to the next UI turn; preserve its generation/disposal/idempotence checks.
- Explicit ribbon actions call TaskPaneControl.RequestContentFocus before posting their page action: DOM focus alone leaves the native WebView unfocused. A pending first-open request survives only while the pane owns focus; background updates and recovery do not request focus. Run tests/scripts/WebViewFocus.Smoke.ps1 with Windows PowerShell 5.1 -STA (also x86) for real WebView native/DOM focus, queued initialization and no focus theft. This isolated smoke does not qualify Narrator inside Outlook.
- `TaskPaneControl.cs` delegates navigation and message trust to `EmbeddedPageBoundary.cs`: only the expected initial HTML navigation is allowed, committed document and message sources must both be `about:blank`. Browser exits recreate each affected WebView after the environment exit event, retaining the coordinator/replay and queued messages. Initialization generations reject stale callbacks; failed initialization offers one explicit retry without a loop. Renderer exits reload; GPU/utility exits keep the healthy document. Run tests/scripts/WebViewRecovery.Smoke.ps1 in Windows PowerShell 5.1 -STA for isolated two-pane runtime checks; this does not qualify Outlook installation.
- `PaneOperations.cs` distinguishes Stop, which retains the current result until End, from Cancel/new turn, which discards it. `AnalysisFinalization` keeps the email list already on screen when the final request is stopped, without another request. Read `ResultToken(cts)` at save time after intervening awaits. Test both orchestrators and `PaneJobs.cs`: idempotent Stop alone does not prove the list survives the final request. Replay uses `turnId`; retain one bubble/result across page reloads (`JobReplayPane.Tests.cjs`).
- Draft selection replacement uses Word `Selection.Range.Text` with an expected-selection check, independently of `Options.ReplaceSelection`; trace `OutlookDataService.Compose.cs` and `TaskPaneCoordinator.Compose.cs` together.
- Generated HTML prepended to new/reply bodies uses `DraftFormatter.ToGeneratedHtml`: v1 provenance comments scope only the generated fragment before the signature/original. This self-declared signal has a local ConfigTool detector but is unauthenticated. A175 installed trials lost the begin comment in Word ordinary/filtered HTML and in new-mail export after a synthetic signature edit; after MSG reopen both comments were absent. Local MIME encoding preserved the inspected states, with one added terminal newline in three 8bit cases. Do not treat these failed persistence cases as qualified coverage; DOCX, OpenReply, Word selection/plain text/clipboard and real transport remain unqualified. Never infer complete provenance or conformance from a recognized marker.
- Tests link COM-free Outlook sources explicitly in `tests/OnlyWorkspace.Tests/OnlyWorkspace.Tests.csproj`. The extractor reference removes the global `TargetFramework`; forcing net48 there creates a second MSBuild instance writing the same output. Keep `TestTfmsInParallel=false`: both test targets share the interactive desktop. Keep `ArchiveIndexerInteractiveTests` in `WinFormsCollection`: `Current` and `InteractiveBegin`/`InteractiveEnd` affect every indexer in the test host.
- Pane width enforcement waits for resize quiet and mouse release, then makes at most four attempts with a reentrancy guard; never write TaskPane.Width during the splitter drag or inside SizeChanged. The HTML viewport retains 340 CSS pixels with horizontal scrolling below that size. WebViewFocus.Smoke tests real layout at 380/190/120 and the production native guard with an ignored-write fixture; these do not qualify monitor DPI or reproduce the reported full disappearance. Keep Office width units distinct from physical/CSS pixels when interpreting logs.
- Choose an existing test class for the affected behavior; for example, `dotnet test OnlyWorkspace.sln -c Release --filter "FullyQualifiedName~PaneOperationsTests" --nologo`. Runtime boundary checks and their environments are in `docs/tecnico/verifica.md`; isolated tests do not qualify an installed Outlook build.
- Lightweight selection headers must include both EntryId and StoreId (from the parent MAPIFolder); a subject and EntryId alone do not identify the source for reconstruction or cross-store actions. Keep COM reads on the UI STA and release the parent.
- Selection context is metadata only: `context_update` carries EntryId, StoreId and subject; `stream_context` identifies the source actually used by a result. Keep those displays separate. A compose window or inline reply overrides the original selected email. Ribbon visibility callbacks must read only lightweight metadata on the UI STA and never create a pane; recheck selection on click. Reply instructions bind their source when armed, while selection changes exit that mode without discarding typed text. Chat, analysis and Briefing do not require selection. The `reconstruct` preset belongs to Cerca e analizza and requires an explicit reading-email seed; it remains local without an AI profile, with a separate summary action. SelectionActions, PanePolicy, RibbonXml and the real WebViewFocus smoke cover these rules; Office Explorer/Inspector still require an installed-build trial.

- A174 pane cards: subjects are outside action buttons; summaries retain their full text and clamp only the preview. The shared ResizeObserver must unobserve cards before a renderer replaces them. rememberView/restoreView retain keyed details, summary expansion, scroll and focus only for the same reconstruction seed. Test exact StoreId/EntryId destinations, not subject matches. Ribbon Svuota chat uses getEnabled with a targeted one-second invalidation; callbacks must never create a pane, and Quit/disconnect stop/dispose its timer. The three top sections are Chat/Posta/Storico; Stato opens through Archivio/IA.

- Agenda/task saves use host result/item/request identities: show success only after the individual host outcome; keep failed items retryable and reject duplicates/stale replies. Data egress uses explicit per-profile grants (notice4) bound to destination, permissions and both resolved keys; only ConfigTool accepts/revokes, and the pane rechecks before transport.

- Build/test output paths are evaluated by MSBuild; `ONLYWORKSPACE_RUNTIME_ROOT` enables checkout-isolated central artifacts. Use `scripts/build-paths.ps1` rather than hardcoded bin/obj paths. Tests receive source and add-in paths as generated assembly metadata; managed fixtures are retained. See `docs/tecnico/output-locali.md`.
