# LLM workflow

- For archive search, local facts and persisted reader revisions use the [archive skill](../onlyworkspace-archive/SKILL.md). The archive card generator is removed; encrypted conversation/AI-response history remains active when enabled. Historical acceptance records do not authorize new provider calls.

- Current cloud boundary: DataEgressNotice5, ConversationPolicy7 and catalog2. CloudFactsRequest keeps original values and restoration on the PC; CloudRequestGuard and LlmRequestDispatcher accept only the embedded cloud.facts template and verified opaque fact references. Free text, mail-derived domains and unverified web queries are blocked before HTTP; synthetic probes stay separate. The evidence packs below describe local preparation, not permission to send originals. See docs/tecnico/pseudonimizzazione.md.

- E5 mail retrieval: explicit fact filters are parsed locally, never discarded for an unfiltered Outlook fallback. Archive queries expand their seed results through `ExpandRelated`, keep permitted stores/attachment policy during graph traversal and label out-of-filter messages. Latest-N selects seeds before expansion. Merge archive/Outlook copies by Message-ID while retaining physical locations; without it use StoreId/EntryId only. A205: multi-email answers (chat, Cerca e analizza, follow-up questions, `FollowUpCoordinator`) build a chronological `MailEvidencePack` (assembled locally from whole originals, or literal local facts at Minimal exposure) and prepare one structured request (`mail.answer`, `mail.table`, `followup.status`), subject to the cloud boundary above; `MailAnswerVerifier` checks amounts, dates and codes against the cited email and marks the rest unverified. List/count requests end with the local list (`MailRequest`). Never reintroduce per-email notes, model condensation or continuations of a structured answer; the local graph does not authorize automatic card regeneration. For local profiles the calendar scan sends locally filtered candidates as whole originals within policy, or literal local facts at Minimal exposure, in one `calendar.scan` request; external dispatch uses only the typed cloud contract, and each item carries `source` and the literal `date_text`, checked by `MailAnswerVerifier.Verify(items, pack)`; unverified items stay listed but unselected.

- Trace transport in `src/OnlyWorkspace.Infrastructure/Llm/`, context rules in `src/OnlyWorkspace.Core/Context/`, templates in `prompts/`, and orchestration in `src/OnlyWorkspace.Outlook/UI/TaskPaneCoordinator*.cs`. Follow-up also uses `src/OnlyWorkspace.Infrastructure/Llm/FollowUpCoordinator.cs`: GetArchivedBodyAsync serves acquired precedents first; the Outlook resolver handles missing originals. Preserve the UI synchronization context for Outlook reads and keep model work on plain data.
- `LlmHttp` refuses redirects, including same-authority redirects; configure the final endpoint. Use computed `LlmProfileConfig.IsExternal` for destination policy, never the editable `External` flag alone. `ModelRequestContext` checks the complete model input, including schema/tools; the pane uses `LlmRequestDispatcher` to recheck policy and reject late results. Keep pre-web and post-web checks; context overflow stops the current action without an automatic continuation.
- The pane's cloud disclosure comes from the dispatch callbacks, never from CreateLlmClient: list/count/local-fact/empty answers may create an unused client. WebSearchService notifies immediately before external HTTP, after a local Ollama query if any; marshal that callback to the captured UI context and preserve the originating turn so a late request cannot mark a later answer. P1DispatchPolicyTests, WebSearchServiceTests and the real net48 factory test in PanePolicy cover idle, rejected and dispatched requests.
- ModelServiceStatus connection checks capture the configuration generation before awaiting; discard stale status and UI results after profile, credentials or policy changes. Keep stream masking, opening and dispatch callbacks inside the request's try/finally, including synchronous failures; local masking refusals give no service verdict. ModelServiceStatusTests injects a deterministic masking refusal and exercises synchronous opening failures.
- Keep the first-response deadline and cancellation alive through HTTP status/error-body processing and stream opening; response disposal must finish pending reads on net48 too (`HttpErrorCancellationTests`). Local budgets must be positive and at most `ProviderCatalog.ComputeBudget`, including output and margin; invalid dispatch must fail before transport, never become unlimited (`ContextBudgetCoherenceTests`).
- Read completion reasons from `ILlmClient.LastCompletion`, independently of `LastTokenUsage`. A parseable JSON answer does not prove completeness; explicit length/context termination must reach `ModelOutput.EnsureComplete` even without `usage`: structured answers are refused when cut (no continuation), streamed text reports truncation. Test SSE, plain JSON fallback, late usage, reset between requests, refusals and premature stream closure in the affected `*ClientTests`.
- OpenAI-compatible, Ollama, Gemini and Anthropic publish usage only after both nonnegative integer input and output counts are observed; merge cumulative partial events without replacing missing fields with zero. Anthropic's `message_start` output count is initial: the final output observation comes from `message_delta`. `ProviderCompletionTests` and the actual net48 single answer (cut answer refused) in `PanePolicy.Tests.ps1` cover this; absent or partial usage never proves zero consumption.
- `ConversationPolicy` revision7 binds history to destination, provider/model and data permissions. `WithPriorTurns` uses `HistoryChatMessage.ModelContent` when present (including explicit empty omission), never the local-only part of `Content`. Agenda source bodies and origin notes remain local; ModelContent separates reusable model context from full presentation, and external dispatch remains bound to the typed contract. A missing or changed policy preserves history for display and starts a separate conversation at the next message; never infer an old policy from the current profile ID. `PanePolicy.Tests.ps1` exercises the real net48 pane methods and isolated CLI import.
- Keep prompt text in `prompts/*.json`, shared rules in `prompts/fragments.json`, and variable data out of the system message. Follow `docs/tecnico/architettura.md#prompt`, including its documented exceptions, and bump the template `version` when text changes. `PromptCatalogTests` checks rendering and the section layout of the restructured templates; it does not measure answer quality.
- The [fidelity corpus](../../../tests/fixtures/fidelity/README.md) and scripts/measure-fidelity.ps1 measure literal local facts only, without configuration or provider calls. Historical generative captures remain immutable; transport and answer tests are covered separately by PanePolicy and the affected client tests.
- Perplexity uses the Sonar `/v1/sonar` messages/choices contract, not Agent API input/typed events. `PerplexityContractTests` verifies payload, plain/SSE structured output, usage/completion and source metadata in offline fixtures. Numbered markers stay in text; citations/search_results are not promoted to app-verified URLs. No configured account was available for live qualification; see `docs/admin/provider-ia.md`. Do not migrate by changing only the URL.

- Use `ProviderCatalog` (`src/OnlyWorkspace.Core/Models/ProviderCatalog.cs`) for API-family routing and `GetModelInfoAsync` for model capabilities. Check rendered messages before model calls, including added web evidence; preserve the whole selected inputs within the exposure policy. On local context overflow, stop with a context error instead of silently truncating evidence. Cloud limits come from the provider; do not add provider fallback. Qualification limits are in `docs/tecnico/verifica.md` and open work in the SecondBrain tracker.
- Route Web Search through `WebSearchAction`, configured profile permissions and capability/probe state. Do not infer support merely from the provider name or tool acceptance: require actual search evidence and HTTPS sources. Keep web findings separate from Outlook facts. In `WebSearchService.cs`, tool acceptance alone must not mark a capability probe supported; pane actions may continue without web evidence with a declared coverage limit, while cancellation still stops them.
- Chat intent uses `IntentClassifier.ClassifyLocal` without model transport; preserve periods, sender/person names, quoted terms and residual clues. Briefing/calendar use `ActionFactsAsync` with exact `ArchiveQuery.EmailRefs` on pipe v15 and scoped stores, literal local facts at Minimal exposure and original bodies for local processing at Standard/local exposure. Briefing renders through `BriefingContext` and the permitted-attachment path; its data-only completion stage `CompleteBriefingAsync` is exercised by the real net48 factory and synthetic HTTP capture in `PanePolicy.Tests.ps1` (optional `-EvidenceDirectory` keeps the payloads); refinement keeps the complete draft. PEC/Gmail mailbox questions leave `LocalChatIntent`; keep the explicit coverage notice when general chat cannot apply the requested mailbox filter. File-reader changes belong in [attachments](../onlyworkspace-attachments/SKILL.md).
- Calendar Minimal (A214): `ExecuteCalendarScanAsync` creates the checked client with `wholeEmails:false` and branches to scoped facts before any original/PEC/attachment read. Missing facts are counted, never replaced by a body. `includeDetails:false` removes subject/sender/link reasons from both the rendered packet and date verification, retaining citation/date and local source links. Minimal history stores only model item fields in `ModelContent`, without locally appended origin notes; keep the generic action label so a scope label cannot re-enter a follow-up. `PanePolicy.Tests.ps1` runs the entire scan with a synthetic header resolver, isolated archive and real loopback HTTP: Minimal/Standard/local, six no-dispatch guards and DPAPI reopen/follow-up. The uninitialized data service has no Outlook application; existing-task inventory and real Office collection are not qualified by this fixture.
- Web search instructions live in `web.search.json`, separated from the bounded request data. Keep only sources cited in the displayed answer/history (`WebCitations`), preserving `CitationNumber`. The 6,000-character search input limit matches the accepted data notice: a longer request sends only its end, `WebSearchResult.InputCut` is set and the pane shows `WebSearchService.InputCutNotice` under the answer (A44). Raising the limit needs a new versioned notice and acceptance first; do not remove it as a routine refactor.
- Structured extraction keeps all valid fields/rows/actions; ExtractionDiagnostics reports invalid-entry counts/reasons independently of provider truncation. Preserve diagnostics through pane render, CSV/TSV, full extraction history and calendar scans. Do not restore the old 40/200/10 caps or silently shorten action titles.

- Run the affected `*ClientTests`, `WebSearchServiceTests`, `ContextBuilderTests`, `WholeActionInputTests` or `FollowUpCoordinatorTests`. `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/scripts/PanePolicy.Tests.ps1` exercises actual pane methods with isolated data. Optional `OllamaLive.Tests.ps1` uses pwsh and test net10 output; pass a model actually present on the loopback endpoint. Fixture results and prompt rendering do not qualify real-model fidelity; record that separately in `docs/tecnico/verifica.md`.

- A221: external dispatch collects a cancellable local identity snapshot before the versioned pseudonymization pipeline. Keep every contact (no search cap), STA slices/COM release, authorized archive-store scope and keyset paging. Local amount/date profile options default false; cloud protection is mandatory and bound to conversation policy7. Audit metadata only, DPAPI, cross-process lock, 30-day expiry of this ledger only; pre-dispatch audit failures block transport. Details: docs/tecnico/pseudonimizzazione.md.

- Notice5 per-profile grants bind canonical endpoints, exposure, effective attachment/web permissions, pseudonymization settings and both resolved vault credentials using salted fingerprints. Accept/AllowsModel/AllowsWeb callers pass the resolver; host-only acceptance never authorizes dispatch. Recheck pending config changes and grants just before model/web HTTP. Probes send synthetic inputs and remain outside this gate.

- Chat/local mail listings and archive-fact answers run before client creation; a zero-result list is local too. Keep profile/history freshness checks separate from egress permission. The real PanePolicy Chat fixture substitutes only Outlook folder enumeration and compose context, and verifies no HTTP without consent.
