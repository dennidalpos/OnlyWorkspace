# Archive workflow

- Current format13, pipe15, attachment reader2. Tray owns the encrypted DB; add-in uses the SID-checked pipe. Update both peers together and reject older versions. Outlook Object Model access stays on UI STA; `ArchiveIndexer` collects only open stores. Trace storage in `src/OnlyWorkspace.Infrastructure/Archive/`, collection in `Services/ArchiveIndexer.cs`, pane in `UI/TaskPaneCoordinator.Archive.cs` and `TaskPaneCoordinator.Flow.cs`.
- Formats11/12 upgrade through `ArchiveDb.Migration.cs`, before serving requests and under ownership. First make an encrypted SQLite paged backup with DPAPI key and SHA-256 manifest; reopen raw, check every integrity result and compare retained data. Production copies live outside the active archive at `%LOCALAPPDATA%/OnlyWorkspace/archive-migration-backups`. Never prune them automatically. Errors/cancellation roll back the transaction. Unknown formats are refused, never rebuilt by dropping acquired originals. `ArchiveRebuildTests` covers restoration, failures, WAL, data equality and derived recovery.
- No automatic model generation, card APIs/prompts, mailbox cloud grants, quotas or accounting remain. Chat/search/briefing/calendar use originals or literal local facts. Exposure0–2, legacy Full/3 reads as Standard; notice3 and conversation policy5 remain explicit. Historical captures stay immutable; `measure-fidelity.ps1` measures only local facts without configuration or providers.
- Original bodies, attachment text, email identities and user decisions are retained. Missing FTS/code/fact indexes recover from these texts. Reader revision and file SHA-256 are independent: stale cached text must not be served until revalidated. Same-hash corrections invalidate shared search/facts; reject stale worker commits. Compressed/executable/unsupported archive attachments keep metadata only, including nested children; MSG/EML/P7M and Office remain readable. Reference is never a read document. Generic extraction and security inspection keep their separate policies; see [attachments](../onlyworkspace-attachments/SKILL.md).
- E5 search keeps typed fact filters before paging and isolated pending-source fallback; an empty code queue must not scan every original. Store/attachment restrictions apply during traversal, so excluded stores cannot bridge chains. Expand through identifiers and grounded shared references, preserving physical StoreId/EntryId copies and sent UTC ordering; no subject/date deduplication. PEC facts-only data must never supply graph links or prompts. Run ArchiveSearchEvolutionTests and FlowPane/PanePolicy script checks.
- Search trigger revision2 queues distinct, absent email ids before inserting. SQLite's outer UPSERT DO UPDATE can override a trigger's OR IGNORE with ABORT: exercise shared-content corrections through SaveBody/StepBodies, including pending jobs and repeated attachment references. Replace persisted trigger definitions transactionally; preserve texts, code indexes and pending jobs. ArchiveSearchEvolutionTests and ArchiveIndexerInterruptionTests retain their archives under ONLYWORKSPACE_TEST_ARTIFACTS when set.
- Scope: saved stores=[] means all, including closed/future stores; ArchiveScope.ForQuery maps unauthorized to deny-all. DB null=all, empty=none. Keep search, flow, related expansion and visible Outlook additions within this boundary.
- Local facts use extractor revision3 and disposable fact jobs; extract outside the engine lock and recheck identity/body/version/policy before commit. Preserve exact decimals, source offsets, labelled deadlines and attachment opt-out. Recovery is local and resumable; missing facts are not replaced with whole originals at Minimal exposure.
- Reconstruction is the local `reconstruct` preset in Cerca e analizza, before any model factory, with an explicit StoreId/EntryId seed and stale-request rejection. Summary is a separate action. No case state/closure APIs or active tables remain; historical closures survive only in verified migration backups.
- Incomplete inventories, unreadable folders and closed stores never prove absence. Cache copies require Outlook MAPI_E_NOT_FOUND; old orphan identities in `archive_source_checks` use negative ids and still require confirmation. Keep those checks independent from removed generated content. Last-copy deletion removes unshared text and whole dependent history conversations, including uncited sources.
- Folder status partitions completed, pending and failed folders: FoldersDone excludes current errors even when the stored done bookmark is true; Remaining subtracts FoldersFailed, and the percentage excludes failures. Keep stats and per-store coverage consistent. ArchiveFolder projects corrected recovery advice for previously saved messages without rewriting errors/bookmarks; do not infer trash/deletion from a path or suppress an unverified reading failure. ArchiveMetricsTests and ArchiveFactStorageTests cover reopen and recovery.
- History invalidation writes the DPAPI ledger first under its cross-process lock. Keep `archive_deletions` until every affected file is verified and WAL checkpoint succeeds; retain corrupt/unreadable files for recovery. Never quarantine them automatically. Preserve ArchiveMirrorTests and source checks when changing deletion.
- After Release build run targeted Archive* tests, ArchiveRecovery/ArchiveCapacity script checks, net48 smoke x64/x86 and relevant PanePolicy coverage. Isolated archives do not qualify installed Outlook, real mailbox capacity, power loss or other PCs. AGENTS.md owns shared gates; docs/tecnico/verifica.md owns current qualification limits.
