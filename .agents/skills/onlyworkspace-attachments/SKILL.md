# Attachment extraction workflow

- Archive extraction uses `--archive` and shared `AttachmentTextFormats`: generic compressed files, executables and unsupported formats are metadata references, including nested children of MSG/EML/P7M. Office/ODF packages remain readable. Keep `reference` distinct from a read document and from a temporary failure; preserve name/type/size through SaveBody/Search/GetOriginal. MIME nested references explicitly label encoded size. Reader revision 2 invalidates previous cached text/derived indexes without deleting paid cards or bodies. The generic reader and `--security` still inspect ZIP contents; never apply archive exclusions to security inspection.

- `.ics` is read as whole text by the isolated helper, including inside supported containers; validate VCALENDAR/VEVENT/VTODO structure without following URLs. `ArchiveFactExtractor` preserves folded-source offsets, all-day/UTC/floating/TZID values and recurrence rules without expanding them. Invalid/truncated inputs cannot claim complete text. `ArchiveFactsTests` runs the real helper for direct and nested calendars.
- Archive receipt data is intentionally separate: `ArchiveAttachmentReader` persists `daticert.xml` as `facts-only` for the local fact extractor, never for FTS/model text. Keep inline images excluded and preserve the existing pane receipt exclusion. Reader changes and local-fact extractor revisions are separate contracts.

- Start at `src/OnlyWorkspace.Infrastructure/Security/AttachmentTextExtractor.cs` and `src/OnlyWorkspace.AttachmentExtractor/Program.cs`; readers are `ContentReader*.cs`. `docs/tecnico/allegati.md` describes supported formats and limits. Trace the consumer too: `ArchiveAttachmentReader.cs`, `TaskPaneCoordinator.Analysis.cs`, or security attachment handling in `TaskPaneCoordinator.cs`. Analysis uses `DocumentOutcome.ApplyExtraction` in Core `Agents/MailAnalysis.cs`: only `WasRead` contributes text; incomplete containers retain their cause instead of always becoming oversized.
- The helper is a net48 executable with its own dependency versions. `FindHelper` probes beside the loaded Infrastructure assembly and AppDomain base directory, checking `extractor/` first. Test output and packaging copy the helper into that subfolder; building only the Outlook project does not establish the same layout. Keep its project-reference metadata in `tests/OnlyWorkspace.Tests/OnlyWorkspace.Tests.csproj` consistent with the solution build.
- `Program` prints `AttachmentExtraction` JSON on stdout; maxChars 0 requests macro inspection without text. `--security <file>` prints `AttachmentInspection` (static script/page/link reading for the security check, `ContentReader.Security.cs`, rules in Core `ScriptStaticRules`/`HtmlActiveContent`): its hooks in `Read`, `ReadNestedFile`, MSG/EML bodies and ZIP walking are inert when `_inspection` is null, so archive text and `ReaderRevision` never change; fixtures stay inert (run-time assembled commands, `.invalid` hosts). Check `Problem`, `Error` and `Truncated`, not just exit code or nonempty text. Macro support (`IsSupported`) differs from text support (`HasTextReader`); opening P7M content does not verify its signature.
- OCR (E8) is `ContentReader.Ocr.cs`: Windows.Media.Ocr/Windows.Data.Pdf through the compile-only `Microsoft.Windows.SDK.Contracts` metadata. Every scanned page or image frame must reach `MinCharsPerTextPage`, else the whole document is `scanned`; no recognizer for the profile languages is `ocr-unavailable`; the administrator's `attachmentOcr` off passes `--no-ocr` (state `ocr-off`, nothing deleted) and turning it on requeues unread scans once through `ArchiveDb.ConfigureOcr`. Check languages with `OnlyWorkspace.AttachmentExtractor.exe --ocr-languages`; `OcrExtractionTests` accept both outcomes so CI runners without a recognizer still pass.
- MSG, EML, ZIP and P7M share expansion/depth accounting in `ContentReader.Msg.cs`, `ContentReader.Containers.cs` and `ContentReader.Signed.cs`. Count decoded bytes actually written, propagate unread nested content through `LimitedText.Incomplete`, and preserve format/extension handling. Do not reset shared budgets per nested file or treat a partial container as fully read.
- PDF extraction reconstructs page layout and applies the 25-alphanumeric threshold to every nonblank page. Blank means no text, images or paths; sparse pages remain conservatively incomplete. Exercise mixed text/scans in both orders and blank/decorative-image pages as well as text-only documents. Propagate completeness to archive and analysis consumers. Archive caches text by SHA-256 plus reader revision; invalidate old completeness claims and suspend derived/unknown saved cards without deleting them when extraction semantics change.
- Keep the common deadline across parent exit and both output streams in `ProcessRunner.cs`. `SuspendedProcess.cs` assigns the hidden suspended child to a kill-on-close Job Object before resuming; timeout returns null, user cancellation throws, and descendants retaining streams must terminate too. Direct helper invocation does not exercise this isolation boundary.
- Security inspection retains the mutable extraction result on failure, including known format and macros; static visits run in the reader's finally so a text-reader error cannot skip the static checks. Written URLs are deduplicated only by complete destination/visible address, never an arbitrary suffix. `AttachmentInspectionTests` exercises short link labels and a truncated OLE Word file with detected VBA through the real helper.
- PDF security compares whole, case-sensitive names after one #xx decoding pass (ISO 32000-1, 7.2.2/7.3.5). Encoded delimiters remain part of the name, and longer names must not match JS/JavaScript/Launch. OpenAction alone may select an internal destination; do not classify it as active content. The raw scan does not inspect compressed object streams or prove the absence of actions. AttachmentInspectionTests exercises uncompressed synthetic PDFs and nested attribution through the real helper; ONLYWORKSPACE_TEST_ARTIFACTS retains those inputs when set.
- Example targeted check from the repository root: `dotnet test OnlyWorkspace.sln -c Release --filter "FullyQualifiedName~AttachmentExtractionTests|FullyQualifiedName~AttachmentContainerTests|FullyQualifiedName~PdfLayoutExtractionTests|FullyQualifiedName~ProcessRunnerTests" --nologo`. These test synthetic files and the actual helper process. Use [archive](../onlyworkspace-archive/SKILL.md) for persistence/invalidation and [LLM](../onlyworkspace-llm/SKILL.md) for model input policy.
